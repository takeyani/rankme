# RankMe システム仕様書

**バージョン**: 2.5  
**作成日**: 2025-02-13  
**ステータス**: ドラフト

---

## 1. システム概要

**RankMe** は、女性の顔写真をもとに**プロのスカウト実務基準に対する近さ**をAIで数値化し、その根拠に基づいた改善アドバイスを提示する**診断システム**である。

- 一般的な美醜評価ではなく、**スカウト現場の評価基準の再現**を目的とする。
- 判定エンジンは Docker Compose で起動可能とする。

---

## 2. 診断の流れ

1. ユーザーが顔写真をアップロードする
2. AIが教師データとの類似度から**ランク（1〜10）**を判定する
3. 判定結果に基づき、上位ランクに近づくための**改善アドバイス**を生成する
4. **診断レポート**を表示する

---

## 3. 機能要件

### 3.1 コア機能

| ID    | 機能                 | 説明                                                                                  | 優先度 |
| ----- | -------------------- | ------------------------------------------------------------------------------------- | ------ |
| F-001 | 画像アップロード     | ユーザーがWeb画面から顔写真を1枚アップロードできる                                    | 必須   |
| F-002 | ランク判定（AI）     | 教師データとの類似度に基づきランク（1〜10）を算出する                                 | 必須   |
| F-003 | 改善アドバイス生成   | 判定結果と教師データの傾向から、上位ランク向けの改善ポイントを提示する                | 必須   |
| F-004 | 診断レポート表示     | 現在のランクと改善アドバイスのみを表示する                                            | 必須   |
| F-005 | 診断結果のDB保存     | 診断結果（ランク・アドバイス等）をDBに保存する。DBは**外部インフラ**（GCP想定）とする | 必須   |
| F-006 | 履歴表示             | 保存した診断結果の履歴を一覧・詳細表示する                                            | 必須   |
| F-007 | 判定方法の切り替え   | AIの**モデル・学習方法**を複数実装し、設定で切り替え可能にする                        | 必須   |
| F-008 | 顔に点数をつけるUI   | 診断結果を**顔に対して点数（ランク）をつけるシンプルなUI**で表示する                  | 必須   |
| F-009 | ラベリング手動追加UI | 教師データの拡張・再ラベリングのため、**ラベリングを手動で追加するUI**を用意する      | 必須   |

### 3.2 ユーザーストーリー

1. **スカウト基準にどれくらい近いかを知りたい**
   - ユーザーがWeb画面で顔写真を1枚アップロードする
   - システムがAIで教師データとの類似度からランク（1〜10）を判定する
   - 診断レポートで現在のランクと改善アドバイスを受け取る

2. **運用側がAIを簡単に起動したい**
   - 開発・運用者が `docker compose up` でWeb＋AIをまとめて起動できる

### 3.3 画面・画面遷移（想定）

```
[トップ / アップロード画面]
    │
    ├─ 顔写真選択（ドラッグ＆ドロップ or ファイル選択）
    ├─ 「診断する」ボタン
    │
    ▼
[診断中表示]（ローディング）
    │
    ▼
[診断レポート画面]
    ├─ 現在のランク（1〜10）
    ├─ 上位ランクに向けた改善アドバイス
    └─ 客観性・透明性の明示文（§7 参照）
```

- **トップ**: タイトル「RankMe」、アップロードエリア、送信ボタン、「履歴を見る」リンク等
- **診断レポート**: ランク・改善アドバイスのみ表示。必要に応じて「もう一度診断」でトップへ
- **履歴一覧**: 保存済み診断結果の一覧。外部DB（GCP）から取得して表示。各件の詳細（ランク・アドバイス）を表示可能とする
- **ラベリング管理画面**（管理者・ラベラー向け）: 教師データ拡張用。画像を登録し、ランク（1〜10）を**手動で付与**するUI。一覧表示・編集・削除を想定。

## 4. 教師データ仕様

| 項目       | 内容                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 評価段階   | **10段階**（ランク 1〜10）                                           |
| データ規模 | **各ランク100枚、合計1,000枚**の顔画像                               |
| ラベリング | **プロのスカウト実務者**による統一基準でラベリング                   |
| 目的       | 美醜の一般評価ではなく、**スカウト現場の評価基準の再現**を目的とする |

**ラベリングの統一**: 教師データの**ラベリング・アップデートは、採用する学習方法やモデルに依存せず同一**とする。同一のラベル形式・データソースを全判定方法が参照し、モデルや学習手法を差し替えてもラベリング運用は一つに統一する。

**ラベリングの追加・更新**: 教師データの拡張・再ラベリングは**手動で追加するUI**（§3.1 F-009）で行う。画像の登録とランク（1〜10）の付与を同一UIで実施し、学習方法に限らず同一のデータソースを更新する。

---

## 5. 判定エンジン仕様

### 5.1 判定の原則

- AIは**教師データとの類似度の数学的計算**（またはそれに準じる客観的算出）によりランク（1〜10）を決定する。
- **主観的な判断は行わない**（類似度・学習結果に基づく客観的算出）。

### 5.2 複数実装・切り替え

- **判定方法を複数実装できる形**で設計する。**モデル**や**学習方法**を差し替え可能とする。
- **切り替え方法**: 環境変数・設定ファイル・起動オプションなど、**コード変更を伴わず切り替えやすい方法**で実装する（例: `RANKME_ENGINE=model_a` や設定で `engine: "similarity_v1"` を指定）。
- **共通インターフェース**: 入力（顔画像1枚）と出力（ランク 1〜10、および改善アドバイス生成に必要な情報）の契約を共通化し、実装ごとにこの契約を満たすことで差し替え可能にする。
- Docker Compose では、起動するコンテナ内で選択された判定エンジン（1つ）が動く形、または複数エンジンを同じAPIでルーティングする形を想定する。

### 5.3 入出力

- **入力**: 顔画像（1枚）
- **出力**: ランク（1〜10）。改善アドバイス生成モジュールへ渡すための情報を含む。

---

## 6. 改善アドバイス生成

- 判定結果（ランク）と教師データの傾向をもとに、**上位ランクに近づくための具体的な改善ポイント**を提示する。
- 診断レポートにはこの改善アドバイスのみをテキストとして表示する（ランク以外の数値や類似度の生値はユーザーに表示しない方針とする場合、実装時に定義）。

---

## 7. ユーザー表示内容と客観性・透明性

### 7.1 診断レポートで表示する内容（2点のみ）

1. **現在のランク（1〜10）**
2. **上位ランクに向けた改善アドバイス**

### 7.2 顔に点数をつけるシンプルなUI

- 診断レポートは**顔に対して点数（ランク）をつけるシンプルなUI**とする。
- 顔画像とランク（点数）を一目で分かるように表示し、余計な要素を排した簡潔な画面とする（例: 顔写真 + ランク数値 + 改善アドバイス + 客観性明示文）。

### 7.3 客観性と透明性の明示

レポートには以下を明示する：

- **「本判定は、選別済み画像データとの類似度および傾向分析に基づく客観的結果です。」**
- **「個人の価値や魅力を断定するものではありません。」**

---

## 8. 判定対象の定義

| 区分                   | 内容                                                               |
| ---------------------- | ------------------------------------------------------------------ |
| **判定しているもの**   | スカウト実務基準に対する近さ（教師データとの類似度に基づくランク） |
| **判定していないもの** | 美醜の評価、個人の価値、性格や人間性                               |

## 9. システム構成

### 9.1 アーキテクチャ概要

```
[ユーザー]
     │
     ▼
[Webフロント]  ← 画像アップロード・診断レポート表示
     │
     │ HTTP/API
     ▼
[Webバックエンド / API]  ← リクエスト受付・AI呼び出し・アドバイス生成制御
     │
     ├─ 内部API ──► [AI推論サービス]  ← 判定方法は複数実装・設定で切り替え（Dockerコンテナ）
     │
     └─ 外部接続 ──► [DB（外部インフラ）]  ← 診断結果の保存・履歴（GCP想定：Cloud SQL / Firestore 等）
```

### 9.2 Docker Compose 構成（目標）

- 1つの `docker-compose.yml` で以下を起動できるようにする。
  - **Webアプリ**（フロント＋API＋改善アドバイス生成）
  - **AI推論サービス**（ランク判定エンジン。モデル・学習方法は設定で切り替え）
- 必要に応じてボリューム・**環境変数で使用する判定エンジンを切り替え**可能とする。
- **AI推論サービスは Docker Compose で GPU を使用する**。NVIDIA GPU をコンテナに渡し、推論を GPU で実行できるようにする。

```yaml
# 例（実装時に具体化）
services:
  web:
    build: ./web
    ports:
      - "3000:3000"
    environment:
      - AI_SERVICE_URL=http://ai:8000
    depends_on:
      - ai

  ai:
    build: ./ai
    ports:
      - "8000:8000"
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
    # または runtime: nvidia 等、実行環境に合わせて設定
```

### 9.3 データベース（外部インフラ）

- **DBの配置**: 診断結果の保存用DBは**Docker Compose の外**に配置し、**外部インフラ**として運用する。
- **クラウド想定**: **GCP（Google Cloud Platform）** を想定する。
  - 例: Cloud SQL（リレーショナル）、Firestore（ドキュメント）、BigQuery（分析用）など。実装時に選定。
- Webアプリは環境変数等でDB接続先（GCP）を指定し、診断結果の保存・履歴取得を行う。

## 10. 技術要件・インターフェース

### 10.1 Web

- 画像アップロード: ブラウザから HTTP（multipart/form-data または Base64 等）で送信
- 対応形式: JPEG, PNG を優先（その他は実装時に定義）
- 最大ファイルサイズ: 実装時に定義（例: 1枚 5MB）

### 10.2 データベース（診断結果・履歴）

- **保存対象**: 診断結果（ランク、改善アドバイス、診断日時、識別用ID 等）。アップロード画像は保存しない方針を推奨（§11 セキュリティ）。
- **インフラ**: **外部インフラ**。**GCP** を想定（Cloud SQL / Firestore 等、実装時に選定）。
- **履歴表示**: 保存済み診断結果の一覧取得・詳細表示をAPIおよび画面で提供する。

### 10.3 AI 判定 API（共通インターフェース）

- **入力**: 顔画像（1枚）
- **出力**: ランク（1〜10）、および改善アドバイス生成に必要な情報（実装時に定義）
- **プロトコル**: REST API を想定（例: `POST /predict`、JSON でランク返却）
- **複数実装・切り替え**: 上記入出力の**共通インターフェース**を満たす複数の判定実装（異なるモデル・学習方法）を用意し、**環境変数や設定でどれを使うか切り替え**できるようにする。算出方法（類似度計算・学習済みモデル推論など）は実装ごとに異なってよいが、主観的評価は用いない。

## 11. 非機能要件（目安）

| 項目           | 内容                                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------------------- |
| 認証           | **ユーザー認証は不要**とする。診断・履歴・ラベリングUI ともに認証なしで利用可能とする。               |
| アクセス制御   | **ラベリングUI へのアクセス制御は不要**とする。権限の細分化は行わない。                               |
| 可用性         | 小規模・デモレベルを想定（SLAは必要に応じて後から定義）                                               |
| セキュリティ   | アップロード画像は判定用のみとし、保存しない、または短期保存に留める方針を推奨                        |
| パフォーマンス | 1枚あたりの判定時間の目安を実装時に定義（例: 5秒以内など）                                            |
| 運用           | AIは Docker Compose で起動・停止できることを必須とする。**推論は Docker Compose で GPU を使用する**。 |

---

## 12. 拡張性

本システム構造は、**顔診断に限らず視覚情報の評価・改善支援分野へ応用可能**である。教師データと評価基準を差し替えることで、他ドメインの視覚評価プラットフォームとして拡張できる。

## 13. 用語・定義

| 用語                 | 定義                                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| RankMe               | プロの評価基準をAIで再現する**視覚評価プラットフォーム**。顔診断サービスではない。                    |
| ランク               | 教師データとの類似度に基づく 1〜10 の段階評価                                                         |
| 教師データ           | プロのスカウト実務者によりラベル付けされた、各ランク100枚・合計1,000枚の顔画像                        |
| 診断レポート         | 現在のランクと改善アドバイスのみを表示する画面・出力                                                  |
| AI推論サービス       | ランク判定を行うコンテナ／プロセス。複数実装を設定で切り替え可能。                                    |
| 判定方法（実装）     | 共通インターフェースを満たす、モデル・学習方法ごとのランク算出実装。切り替えで差し替え可能。          |
| 共通インターフェース | 入力: 顔画像1枚、出力: ランク1〜10。全判定実装がこの契約に従う。                                      |
| 外部DB               | 診断結果の保存・履歴用。Docker 外の**外部インフラ**。**GCP**（Cloud SQL / Firestore 等）を想定。      |
| ラベリング手動追加UI | 教師データに画像を登録し、ランク（1〜10）を手動で付与する管理者向けUI。拡張・再ラベリングに使用する。 |
