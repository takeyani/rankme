## 1. エグゼクティブサマリー

### 総合UXスコア: **72 / 100**

RankMeは「顔にスコアをつける」という本質的にセンシティブなプロダクトでありながら、設計ドキュメントにおいて**clinical-professional（医療・診断的）**というトーンを明確に定義し、エンターテインメント的な美容アプリとの差別化を図っている点は評価できる。しかし、倫理的配慮・感情的安全性の設計が十分とは言えず、実装前に対処すべき重大な課題が複数存在する。

### 主要な強み（5点）

1. **明確なデザイン哲学**: 「診断ツールであり美容アプリではない」という位置づけが一貫しており、clinical-professionalトーンがカラーパレット、タイポグラフィ、アニメーション方針まで徹底されている
2. **スコアカラーシステムの設計**: ランク1-10に対応するカラーグラデーション（赤→緑→青）は医療検査の基準値表示を参照しており、直感的で一貫性がある
3. **技術スタックの適切な選定**: shadcn/ui + Tailwind CSS + motion/react の組み合わせは、アクセシビリティ対応とパフォーマンス目標（Lighthouse 90+）の両立に適している
4. **詳細なエラーハンドリング設計**: 22種類のエラーコードが定義され、ユーザー向けメッセージが日本語で用意されている。タイムアウト処理（5秒ソフト/30秒ハード）も実用的
5. **レスポンシブ設計の充実**: モバイルファーストの方針が明確で、画面ごとのブレークポイント対応が具体的に定義されている

### 重大な課題（Critical Issues）

1. **倫理的UX設計の不足**: 顔にスコアをつけるプロダクトにおいて、ユーザーの心理的安全性を確保するための設計が免責テキスト2行のみで、極めて不十分
2. **認証なしでの履歴機能の矛盾**: 認証不要でありながら履歴表示（個人の診断結果一覧）を提供する設計に、プライバシーとデータ所有権の問題がある
3. **ラベリングUIのアクセス制御不在**: 教師データ管理画面に認証・アクセス制御が一切なく、悪意ある操作（全データ削除等）への防御がゼロ

### 改善提案サマリー

実装前に最低限対処すべきP0課題が3件、ローンチ前対処のP1課題が5件存在する。特に倫理的UX設計は本プロダクトの性質上、最優先で取り組む必要がある。

## 2. ユーザージャーニー分析

### 2.1 プライマリジャーニー: 診断フロー

```
トップ画面 → 写真選択 → アップロード → 診断中（待機） → レポート表示
```

#### ステップ別分析

| ステップ | 画面 | ユーザーの行動 | 感情状態 | 摩擦ポイント | 推奨改善 |
|---------|------|--------------|---------|-------------|---------|
| 1. 到着 | SCR-001 | サービスの説明を読む | 好奇心 + 軽い不安 | サービスの説明が1-2行と短すぎる。何が行われるか不明瞭 | 診断プロセスの概要（3ステップ表示）、データの取り扱い方針を明記 |
| 2. 写真選択 | SCR-001 | D&Dまたはファイル選択 | 不安 + 躊躇 | 自分の顔写真を提供することへの心理的ハードル。プライバシーへの不安がある | 「画像はサーバーに保存されません」のメッセージを**アップロード前に**表示。カメラアイコンを活用したモバイル撮影導線 |
| 3. プレビュー確認 | SCR-001 | 選択画像を確認し「診断する」を押す | 期待 + 緊張 | プレビュー後の写真差し替え導線が不明確 | プレビュー画像にクリアボタン（×）を配置。「別の写真を選ぶ」リンクを追加 |
| 4. 待機 | SCR-002 | ローディングを見守る | 緊張 + 焦り | 最大5秒の待機。5秒を超えた場合の不安増大 | ステップ表示（画像解析中→照合中→結果生成中）で進捗を可視化。推定残り時間の表示を検討 |
| 5. 結果確認 | SCR-003 | スコアと改善アドバイスを閲覧 | 満足 or 失望/傷つき | **最もセンシティブなモーメント**。低スコアの場合、ユーザーが深く傷つく可能性がある | スコアリビール前に心理的クッション（後述）。低スコア時のアドバイスのトーンを特に配慮。「このスコアはスカウト基準との類似度であり、あなたの魅力とは無関係です」の強調表示 |

#### 重要な摩擦ポイント: 結果表示の瞬間

診断レポート画面（SCR-003）はユーザージャーニーの**最も感情的に脆弱なポイント**である。現在の設計では:

- スコアが5rem（80px相当）の巨大フォントで即座にフェードインする
- 免責テキストはスコアの下に0.75remの小さなフォントで配置
- ランク1-3のユーザーは赤色のスコアを大きく表示される

**問題**: スコアの視覚的インパクトが圧倒的に強く、免責テキストは事実上読まれない。特にランク1-3を受けたユーザーに対する心理的ダメージの緩和策が設計されていない。

**推奨**: スコア表示前に「診断結果について」のブリーフィングテキストを表示し、「この結果はスカウト業界の特定基準との類似度です」を結果表示前に伝える。スコア表示は段階的リビール（まずアドバイスを表示→スコアを表示の順序も検討可）。

### 2.2 セカンダリジャーニー: 履歴確認

```
トップ画面 → 「履歴を見る」 → 履歴一覧（SCR-004） → 詳細表示（SCR-005）
```

#### ステップ別分析

| ステップ | 感情状態 | 課題 |
|---------|---------|------|
| 1. 履歴一覧閲覧 | 振り返り、比較欲求 | **認証がないのに「誰の」履歴を表示するのか不明**。ブラウザ識別（Cookie/localStorage）の場合、別デバイスでは閲覧不可。仕様書に識別方法の記載がない |
| 2. 詳細表示 | 過去の結果との比較 | 顔画像が保存されないため、SCR-005では「画像は保存されていません」のプレースホルダーが表示される。**スコアだけでは過去の診断結果を特定できない**（いつの写真だったか分からない） |

#### 重大な設計課題

1. **ユーザー識別方法の欠落**: 認証不要の仕様（NFR-001）と履歴表示機能（FR-006）が矛盾している。DBに診断結果は保存されるが、どのユーザーの結果か紐づけられない。実装時にCookie/セッションIDでの暫定識別が必要だが、仕様書に記載がない
2. **画像非保存による履歴の価値低下**: 顔画像を保存しない（NFR-004）ことは正しいが、結果として履歴詳細画面は「日時 + ランク数値 + アドバイス」のみとなり、どの写真に対する結果だったか判別できない。ユーザー体験として貧弱

**推奨**: (a) 匿名セッションIDでのユーザー紐づけ方法を仕様に追加、(b) 診断時に任意のメモ/ラベル入力フィールドを追加し、履歴の識別性を向上、(c) 履歴画面でランクの推移グラフを表示し、「変化の可視化」で付加価値を提供

### 2.3 管理者ジャーニー: ラベリング

```
管理画面アクセス → 統計確認 → 画像登録 → ランク付与 → 確認
```

#### ステップ別分析

| ステップ | 課題 |
|---------|------|
| 管理画面アクセス | `/admin/labels` に認証・アクセス制御なし。URLを知っている誰でも教師データを操作可能。**一括削除で全教師データ（1,000枚）を消去可能** |
| 画像登録 | GCSへのアップロード。ネットワーク遅延時のUXが未設計（プログレス表示のみ記載あり） |
| ランク付与 | 1-10のドロップダウン。効率的だが、ラベリング基準（どのような基準でランクを付けるか）のガイダンスがUI上にない |
| 確認 | 即座にPUTが呼ばれる（SCR-006-E07: 「ランク変更時に即座にPUT」）。**確認ダイアログなしの即時保存**はミスオペのリスクが高い |

**推奨**: (a) 最低限のBASIC認証またはパスワード保護を導入、(b) ランク変更時に確認プロンプトまたはUndoバーを表示、(c) ラベリング基準のリファレンスドキュメントへのリンクを画面上に配置

| 1.3.1 情報と関係性 | 見出しレベル定義あり（H1-H4） | 適合見込み | セマンティックHTML構造の実装時に検証必要 |

### 4.2 カラーコントラスト分析

| 組み合わせ | 前景 | 背景 | 推定コントラスト比 | WCAG AA | 課題 |
|-----------|------|------|-------------------|---------|------|
| プライマリテキスト / 背景 | #1E293B | #F8FAFC | 約12.5:1 | 適合 | - |
| セカンダリテキスト / 背景 | #64748B | #F8FAFC | 約4.6:1 | 境界的 | ぎりぎり適合。小さいフォントサイズでは注意 |
| アクセント / 白背景 | #0891B2 | #FFFFFF | 約3.5:1 | **不適合**（通常テキスト） | アクセントカラーをテキストとして使用する場合、コントラスト比が不足する可能性 |
| ランク4スコアカラー | #CA8A04 | #FFFFFF | 約2.8:1 | **不適合** | 黄色系スコアカラーは白背景上のテキストとして使用不可 |
| ランク5スコアカラー | #A3A30A | #FFFFFF | 約2.9:1 | **不適合** | 同上 |
| ダークモード テキスト | #F1F5F9 | #0F172A | 約15.4:1 | 適合 | - |
| ダークモード アクセント | #22D3EE | #0F172A | 約8.5:1 | 適合 | - |

**重大な発見**: スコアカラーのランク3-5（アンバー、ダークイエロー、イエローグリーン）は白背景上でWCAG AAのコントラスト基準を満たさない。デザイン要件書にも「必要に応じてダーク版カラーを使用する」と記載されているが、ダーク版カラーが定義されていない。

**推奨**: (a) ランク3-5のスコアカラーのダーク版を定義（例: #CA8A04 → #92400E）、(b) スコア表示はカラー背景にテキストではなく、カラーボーダー/バッジ + 高コントラストテキストの組み合わせに変更、(c) スコアの数値は常にプライマリテキストカラーで表示し、カラーインジケータ（バッジ、バー、ドット等）を併用

### 4.3 スクリーンリーダー対応

| 要素 | 設計状態 | 課題 |
|------|---------|------|
| スコア表示 | aria-liveで動的更新通知（設計あり） | aria-labelの具体的なテキストが未定義（例: 「あなたのランクは10段階中7です」） |
| スコアカラー | カラーのみで伝達 | カラーだけでなくテキストでもランクの意味を伝達する必要あり（「良好」「改善余地あり」等） |
| アップロードエリア | ドラッグ&ドロップ対応 | キーボード + スクリーンリーダーでのファイル選択フローが未設計 |
| ランクスケールバー | 視覚的インジケータ | aria属性（aria-valuenow, aria-valuemin, aria-valuemax）の定義が必要 |

### 4.4 キーボードナビゲーション

- shadcn/ui（Radix UI）の採用により、基本的なキーボードナビゲーションは確保される見込み
- ドラッグ&ドロップのキーボード代替手段（Enterキーでファイル選択ダイアログを開く）を明示的に設計に追加すべき
- ラベリング画面のキーボードショートカットが未定義

### 4.5 タッチターゲット

- 最小タッチターゲット44px、CTAは48px以上と定義されており適切
- 履歴一覧（SCR-004）のテーブル行がタッチターゲットとして十分なサイズか実装時に検証が必要
- ラベリング画面の削除ボタン（アイコンボタン）のタッチターゲットサイズに注意

## 5. 感情分析 (PADモデル)

### PADモデルによる画面別分析

PAD = Pleasure（快感）/ Arousal（覚醒）/ Dominance（支配感）。各指標は -1.0（最低）から +1.0（最高）のスケール。

| 画面 | Pleasure | Arousal | Dominance | 感情状態の説明 | 設計上の配慮 |
|------|----------|---------|-----------|--------------|-------------|
| **トップ/アップロード** | +0.1 | +0.4 | +0.5 | 好奇心と軽い不安。ユーザーは自発的に行動を開始するため支配感はある | 清潔感のあるUIは好印象だが、写真提供への心理的ハードルを下げるメッセージが不足 |
| **写真選択中** | -0.1 | +0.5 | +0.3 | 緊張感の高まり。「どの写真を選ぶべきか」の判断ストレス | 推奨される写真条件（正面、明るい場所等）のガイダンスがない |
| **診断中（待機）** | -0.2 | +0.7 | -0.3 | 高い覚醒と低い支配感。結果への期待と不安。コントロールを失っている感覚 | パルスアニメーション + ステップテキストは適切。キャンセル機能で支配感を回復可能（ただし「任意」と記載） |
| **結果表示（高スコア: 7-10）** | +0.6 | +0.5 | +0.4 | 満足感と安堵。ポジティブな結果に喜ぶ | 現在の設計は概ね適切 |
| **結果表示（中スコア: 4-6）** | -0.1 | +0.3 | +0.1 | 曖昧な感情。「良くもなく悪くもない」の不満足感 | 改善アドバイスの実行可能性が重要。具体的な次のアクションを提示する設計が必要 |
| **結果表示（低スコア: 1-3）** | **-0.7** | **+0.8** | **-0.6** | **強い不快感と高い覚醒。自己肯定感の低下。支配感の喪失** | **現在の設計は心理的ダメージの緩和策が不十分。巨大な赤い数字の表示は感情的に破壊的** |
| **履歴一覧** | +0.1 | +0.2 | +0.5 | 落ち着いた振り返り。過去の結果との比較 | 時系列変化のビジュアライゼーションがあると、改善の動機付けになる |
| **ラベリング管理** | +0.2 | +0.2 | +0.7 | 業務的な作業感。高い支配感 | 機能性重視の設計は適切 |

### 最重要課題: 低スコア時の感情的安全性

**RankMeで最も危険な瞬間は、低スコア（1-3）が表示される瞬間である。**

現在の設計:
- ランク1-3は赤色（#DC2626 / #EA580C / #D97706）で5rem（80px）の巨大フォントで即座に表示される
- 免責テキストは0.75rem（12px）でスコアの下に配置される
- 視覚的にスコアが支配的であり、免責テキストは読まれない可能性が極めて高い

**ユーザーが受ける心理的影響**:
- 自分の顔に「1」や「2」という数字がつけられる体験は、客観的な診断ツールとして受け止めるには**感情的負荷が大きすぎる**
- 特に若年層ユーザーの自己肯定感に深刻な影響を与えるリスクがある
- 「スカウト基準との類似度」という説明は、低スコアのユーザーには「自分はスカウトに選ばれない」と翻訳される

**推奨される緩和策**:
1. スコア表示前の**同意確認ステップ**: 「結果を表示しますか？この結果はスカウト業界の特定基準との類似度であり、あなたの価値を示すものではありません」
2. **スコアの表示方式変更**: 数字の直接表示ではなく、スペクトラム/バー上の位置として表示することで、「点数をつけられる」感覚を軽減
3. **アドバイスファースト設計**: スコア数値ではなく改善アドバイスを最初に表示し、数値は「詳細を見る」で展開する構成を検討
4. **ポジティブフレーミング**: 低スコアの場合、「改善の余地が大きい＝伸びしろがある」というフレーミングを強調

## 9. 倫理的UX考慮事項

### 9.1 根本的な懸念

RankMeは**人間の顔に数値スコアをつける**プロダクトである。これは本質的に倫理的リスクが高い。設計ドキュメントでは「スカウト実務基準に対する近さ」「客観的な診断ツール」として位置づけているが、ユーザーの受け止め方は設計者の意図通りにはならない。

**ユーザーの認知**: 多くのユーザーは「AIが自分の顔の魅力を10段階で評価した」と受け止める。「スカウト基準との類似度」という技術的な説明は、感情的なインパクトを緩和するには不十分。

### 9.2 感情的リスクの評価

| リスク | 深刻度 | 発生確率 | 対応状態 |
|--------|--------|---------|---------|
| 低スコアによる自己肯定感の低下 | Critical | 高（ランク1-3を受けるユーザーは全体の約30%と推定） | **不十分**。免責テキスト2行のみ |
| 反復利用による依存・執着 | High | 中 | **未対応**。利用回数の制限や注意喚起がない |
| SNSでのスコア共有による他者比較 | High | 中 | **未対応**。共有機能は設計にないが、スクリーンショットでの共有は防げない |
| 若年層への心理的影響 | Critical | 高 | **未対応**。年齢制限やペアレンタルコントロールの設計がない |
| スコアに基づく差別・いじめ | High | 低〜中 | **未対応** |

### 9.3 免責テキストの有効性評価

現在の設計:
- 「本判定は、選別済み画像データとの類似度および傾向分析に基づく客観的結果です。」
- 「個人の価値や魅力を断定するものではありません。」
- 表示位置: スコアの下、0.75rem（12px）

**評価: 不十分**

理由:
1. **フォントサイズが小さすぎる**: 0.75rem（12px）は最小可読サイズギリギリ。重要な免責事項のサイズではない
2. **位置が不適切**: スコア（5rem/80px）の後に配置されるため、ユーザーの注意はスコアに奪われ、免責テキストは読まれない
3. **内容が技術的すぎる**: 「選別済み画像データとの類似度および傾向分析」は一般ユーザーに伝わらない
4. **感情的ケアがない**: 「個人の価値や魅力を断定するものではありません」は否定文であり、「あなたの魅力は多面的です」等のポジティブなメッセージがない

### 9.4 推奨される倫理的UX設計

#### P0: ローンチ前必須

1. **利用開始時の同意画面**: 初回利用時に、サービスの性質と限界を説明し、同意を求める画面を追加
   ```
   このサービスはスカウト業界の特定の評価基準との類似度を算出します。
   - 美醜の評価ではありません
   - 個人の価値や魅力を示すものではありません
   - 結果に心理的な影響を受ける可能性がある方はご利用をお控えください
   [理解して利用する]
   ```

2. **免責テキストの強化**:
   - フォントサイズを0.875rem（14px）以上に変更
   - スコア表示の**上**（前）に配置（スコアの後ではなく前に見せる）
   - より平易な表現に変更
   - 視覚的に目立つデザイン（カード/ボックスで囲む等）

3. **結果表示前のクッション**: スコア表示前に1ステップ挟む（「結果を表示する」ボタン + 簡易説明）

#### P1: 早期対応推奨

4. **年齢確認**: 利用規約に年齢制限（18歳以上推奨）を記載。年齢入力は任意だが、未成年者向けの追加警告を表示

5. **利用頻度の制限**: 同一セッションでの連続診断回数に上限を設定（例: 1時間に3回まで）。超過時に「しばらく時間をおいてからお試しください」のメッセージ

6. **ポジティブフレーミング**: 低スコア時のアドバイスに「伸びしろ」「ポテンシャル」等のポジティブな表現を使用。ネガティブな表現の禁止を明文化

### 9.5 データプライバシーの評価

| 項目 | 設計状態 | 評価 |
