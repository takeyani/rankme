# RankMe デザイン要件

Phase 1 要件定義で使用するデザイン要件 - **RankMe** プロジェクト。
プロのスカウト実務基準に対する近さをAIで数値化する**視覚評価プラットフォーム**。
顔写真からランク（1〜10）を判定し、改善アドバイスを提示する診断システム。

---

## 1. 美的方向性（Aesthetic Direction）

### 1.1 トーン

- [ ] **brutally-minimal** - 厳格なミニマリズム、極端なネガティブスペース
- [ ] **maximalist-chaos** - 最大主義、豊富な視覚要素、大胆な色使い
- [ ] **retro-futuristic** - レトロフューチャー、80s/90sインスピレーション、ネオン
- [ ] **organic-natural** - 有機的・自然、柔らかい曲線、アースカラー
- [ ] **luxury-refined** - ラグジュアリー、洗練、高品質タイポグラフィ
- [ ] **playful-toy-like** - 遊び心、明るい色、丸みを帯びた形状
- [ ] **editorial-magazine** - エディトリアル、雑誌のようなレイアウト
- [ ] **industrial-utilitarian** - インダストリアル、機能性重視、モノトーン
- [x] その他: **clinical-professional** - 医療・診断的な信頼感、客観的で冷静なトーン

> **clinical-professional（医療・診断的な信頼感）**を採用。RankMeは美容アプリではなく、プロスカウト基準に対する客観的な診断ツールである。医療の検査結果レポートや、専門家が使う評価ツールのような、冷静で客観的かつ信頼性の高いトーンを目指す。装飾ではなく「結果の正確さ」が最も重要であるというメッセージをデザインで伝える。

### 1.2 ムード

- [x] professional（プロフェッショナル）
- [ ] playful（遊び心）
- [ ] editorial（エディトリアル）
- [ ] industrial（インダストリアル）
- [ ] elegant（エレガント）
- [ ] bold（大胆）
- [x] その他: **serious（真剣）**, **trustworthy（信頼）**, **minimalist（ミニマリスト）**

> 信頼性と客観性を最優先するムード。ユーザーがスコアを受け取る瞬間に「エンターテインメント」ではなく「専門的な診断結果」として受け止められるデザイン。余計な感情的演出を排し、データと結果に集中させる。

### 1.3 キーワード

- **信頼性** - 専門家が使うツールとしての信頼
- **客観性** - 主観ではなくデータに基づく判定
- **透明性** - 判定プロセスの明示
- **プロフェッショナル** - スカウト実務基準という専門領域

### 1.4 参照サイト

| サイト名 | URL | 参考ポイント |
|---------|-----|-------------|
| 23andMe | https://www.23andme.com | 医療・診断レポートの信頼感のあるUI、クリーンなデータ表示 |
| Apple Health | - | ヘルスケアデータの視認性の高い表示、ミニマルかつ情報密度の高いレイアウト |
| Linear | https://linear.app | プロフェッショナルツールのクリーンなUI、無駄のないインターフェース |

### 1.5 禁止パターン（AI Slop回避）

以下は**使用禁止**:

- [x] Inter, Roboto, Arial等のジェネリックフォント
- [x] 紫グラデーション on 白背景
- [x] 予測可能なレイアウトパターン
- [x] 過剰なドロップシャドウ
- [x] Space Grotesk（AI生成の典型）
- [x] cookie-cutter design

追加禁止パターン:
- グロー効果（信頼性を損なう）
- エンターテインメント/美容アプリ的な美学（ピンク、パステル、キラキラ）
- 過度にカラフルまたは遊び心のあるデザイン
- ネオングラデーションやサイバーパンク風の演出
- 安価な星・キラキラエフェクト
- 円形プログレスバーの安直な使用

### 1.6 差別化ポイント

このデザインを**忘れられないもの**にする要素:

```
- 美容アプリではない → 診断ツールとしての信頼感。
  医療の検査結果レポートのように、シンプルに顔と点数を表示する大胆なUI。
- 過度な装飾を排した、結果にフォーカスするデザイン。
  顔写真とランク数値が画面の主役であり、それ以外の要素は控えめに配置。
- ディープチャコール (#1C2127) とティール (#0891B2) の配色が
  医療機器のインターフェースを想起させ、「診断」としての専門性を伝える。
- スコア表示は大きく太い数字で一目瞭然。カウントアップではなく、
  フェードインで静かに結果を提示する「検査結果発表」の体験。
```

- 本文: **Noto Sans JP** - 日本語の可読性が最も高く、ウェイトバリエーションが豊富。診断レポートやアドバイスの長文テキストを読みやすく表示。
- スコア表示: **DM Sans 700/5rem** - 大きく太い数字で一目で結果がわかる。医療検査の数値表示のような明快さ。

**禁止フォント:** Inter, Roboto, Arial, Space Grotesk

## 3. UIコンポーネント方針

### 3.1 コンポーネントライブラリ

- [x] **shadcn/ui** (推奨) - Radix UI + Tailwind
- [ ] **Radix UI** - プリミティブのみ
- [ ] **Base UI** - MUI のプリミティブ
- [ ] **React Aria** - Adobe のプリミティブ
- [ ] **MUI** - Material Design
- [ ] **Chakra UI**
- [ ] **Ant Design**
- [ ] カスタム実装
- [ ] その他: _______________

> shadcn/uiを採用。Radix UIベースのアクセシビリティ対応済みプリミティブに対して、Tailwind CSSでRankMeのclinical-professionalテーマをカスタムスタイリングする。コピーペースト方式のため、スコア表示カードやラベリングUIなどプロジェクト固有のコンポーネントへの拡張も容易。

### 3.2 スタイリングシステム

- [x] **Tailwind CSS** (推奨) - ユーティリティファースト
- [ ] **CSS Modules** - スコープ付きCSS
- [ ] **Emotion** - CSS-in-JS
- [ ] **styled-components** - CSS-in-JS
- [ ] **vanilla CSS**
- [ ] その他: _______________

> Tailwind CSSを採用。shadcn/uiとの親和性が最も高く、カラーパレット（ディープチャコール、ティール、スコアカラー）をtailwind.config内でカスタムテーマとして定義する。ユーティリティファーストにより、レスポンシブデザインやダークモード切り替えも効率的に実装可能。

### 3.3 アニメーションライブラリ

- [x] **motion/react** (推奨) - 旧 framer-motion
- [ ] **CSS animations** - CSS のみ

- [ ] **GSAP** - 高度なアニメーション
- [ ] **Lottie** - After Effects アニメーション
- [ ] その他: _______________

> motion/react（旧framer-motion）を採用。主な使用箇所:
> - **スコアリビールアニメーション**: フェードイン + 軽いスケール。派手な演出ではなく、静かに結果を提示する。
> - **ページ遷移**: アップロード → 分析中 → 結果表示のスムーズな画面切り替え。
> - **改善アドバイスの表示**: 各アドバイス項目が順番にフェードインするスタガー表示。
> - **全てのインタラクションは200ms以下**。Compositorプロパティ（transform, opacity）のみ使用。

### 4.2 アプローチ

- [x] **モバイルファースト** (推奨) - min-width 方式
- [ ] デスクトップファースト - max-width 方式

> モバイルファーストを採用。一般ユーザーがスマートフォンで自撮りを撮影し、そのままスコアリングする利用シーンが最も多いと想定。写真アップロード、結果表示、改善アドバイスの閲覧がモバイルで快適に行えることを最優先とする。

### 4.3 画面別レスポンシブ方針

| 画面 | Mobile | Tablet | Desktop |
|------|--------|--------|---------|
| トップ/アップロード | シングルカラム。アップロード + 結果表示 | シングルカラム（中央寄せ） | 中央配置、max-width制約 |
| 診断レポート | 縦積み: 顔写真 → スコア → アドバイス | 2カラム: 顔写真+スコア / アドバイス | 2カラム + サイドパネル |
| 履歴一覧 | カードリスト | 2カラムグリッド | テーブル表示 |
| ラベリング管理 | カードリスト + スコア入力 | 3カラムグリッド | 4-6カラムグリッド + サイドパネル |

### 4.4 Safe Area対応

- [x] **必須** - iPhone notch/home bar 対応
- [ ] 任意

> モバイルファーストのため必須。env(safe-area-inset-*) を使用し、iPhone notch/Dynamic Island/home barに対応する。

### 4.5 タッチターゲット

最小タッチターゲットサイズ: **44px**

> 写真アップロードボタン、「診断する」ボタンなど主要CTAは48px以上を確保する。

## 5. 画面別デザイン方針

### 5.1 トップ/アップロード画面

- **ヘッダー**: シンプルに「RankMe」のロゴ/タイトルを配置。サブタイトルに「プロスカウト基準AI診断」等の説明文
- **アップロードエリア**: 画面中央に大きく配置。ダッシュ枠線のドロップゾーン。Lucideの`Upload`アイコン + 「写真をドラッグ&ドロップ または クリックして選択」テキスト
- **CTA**: 「診断する」ボタン。アクセントカラー（ティール）背景、白テキスト。目立つが派手すぎない
- **ナビゲーション**: 「履歴を見る」リンクをヘッダーまたはアップロードエリア下に配置
- **トーン**: 清潔感があり、シンプル。余計な装飾は一切なし

### 5.2 診断中画面

- **ローディングアニメーション**: 控えめで専門的。パルスアニメーションまたはスケルトンUI
- **プログレスインジケータ**: 「AI分析中...」のテキスト + シンプルなプログレスバー
- **トーン**: 落ち着いた待機画面。焦らせない、信頼感のある表現

### 5.3 診断レポート画面

- **レイアウト**: 顔写真 + ランク数値を画面の最上部に大きく配置。これが画面の主役
- **スコア表示**: DM Sans 700/5rem。スコアカラー（ランク対応色）で表示。数字の横に「/10」を小さく添える
- **顔写真**: クリーンなカード内に収める。角丸8px。写真の上にスコアをオーバーレイしない（分離して表示）
- **改善アドバイス**: スコアの下にカード形式で3-5項目。各項目にアイコン + タイトル + 説明文
- **免責テキスト**: 「本判定は、選別済み画像データとの類似度および傾向分析に基づく客観的結果です。個人の価値や魅力を断定するものではありません。」をスコア表示の下に小さいフォント（0.75rem）、セカンダリテキストカラーで表示
- **アクション**: 「もう一度診断する」ボタン

### 5.4 履歴一覧画面

- **レイアウト**: テーブル/カードリスト表示
- **表示項目**: 日付、ランク（スコアカラー付き）、サムネイル
- **ソート**: 日付順（デフォルト）
- **トーン**: データ一覧としてのクリーンさ。shadcn/uiのDataTableコンポーネント活用

### 5.5 ラベリング管理画面

- **レイアウト**: グリッド表示。画像 + ランクセレクター（1-10）
- **一括操作**: 複数選択 + 一括ランク設定
- **検索/フィルター**: ランク別フィルター、日付フィルター
- **効率性**: ラベリング作業の効率を最優先。キーボードショートカット対応
- **トーン**: ユーザー向け画面と統一しつつ、機能性・効率性を優先

## 6. アニメーション方針

### 6.1 基本原則

- **全てのインタラクションは200ms以下**
- **Compositorプロパティのみ使用**: transform, opacity
- **レイアウトプロパティのアニメーションは禁止**: width, height, margin, padding等
- **過度な演出は禁止**: 診断ツールとしての冷静さを維持

### 6.2 画面別アニメーション

| 画面/要素 | アニメーション | duration | イージング |
|-----------|---------------|----------|-----------|
| スコアリビール | フェードイン + 軽いスケール (0.95→1.0) | 200ms | ease-out |
| ページ遷移 | サブトルフェード | 150ms | ease-in-out |
| カード表示 | スタガーフェードイン | 各100ms、delay 50ms | ease-out |
| ボタンホバー | opacity変化 (1.0→0.9) | 100ms | ease |
| アップロードドロップ | ボーダーカラー変化 | 150ms | ease |
| ローディング | パルスアニメーション | 1500ms loop | ease-in-out |

### 6.3 禁止アニメーション

- バウンス効果
- 3Dトランスフォーム
- 複雑なキーフレームシーケンス
- パーティクルエフェクト
- カウントアップアニメーション（静かにフェードインで結果を提示する）
